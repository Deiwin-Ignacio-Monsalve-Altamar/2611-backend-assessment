# Assumptions

> The scenario is intentionally incomplete. Record every assumption you needed to make, and the part it affects.

| # | Assumption | Why I needed it | Part(s) affected |
|---|---|---|---|
| 1 | **Payment key format in Salesforce (`Payment_Key__c`):** Constructed deterministically as `<PROVIDER_UPPER>:<PROVIDER_TRANSACTION_ID>` (e.g., `ANDINA:TRX-CO-5521907`, `QUETZAL:ch_7Hk2Lm9QpZ`, `AUSTRAL:AUS-P-77120`). | `Premium_Payment__c` uses `Payment_Key__c` as its unique External ID for upserts, and multiple lifecycle events (pending -> captured -> refunded) update the same payment record rather than creating separate rows. | Part A, Part B |
| 2 | **Policy number normalization for Andina Pay (Colombia):** Since Andina API v2.3 sends `transaccion.referencia` as entered by the payer, inputs missing the `POL-CO-` prefix or containing whitespace/lowercase (e.g., `000215560` or `pol-co-000198004`) can be normalized to `POL-CO-<9-digit zero-padded number>` if the numeric part matches a 1-to-9 digit policy sequence. Non-matching references are rejected/dead-lettered without retrying against Salesforce. | Prevents `400 INVALID_FIELD` errors on valid Colombian payments while avoiding wasted Salesforce API quota on genuinely invalid policy numbers. | Part A, Part B, Part D |
| 3 | **State machine precedence for out-of-order events:** Terminal/reversal states (`Refunded`) take precedence over `Captured`, which takes precedence over `Pending`. `Failed` is terminal unless a subsequent event carries a strictly newer `statusChangedAt` timestamp (e.g., a retried charge). Equal timestamps break ties by state rank (`Refunded` > `Captured` > `Failed` > `Pending`). | Providers do not guarantee delivery order (FR5), and clock skew of a few seconds can occur across distributed provider nodes. | Part A, Part B |
| 4 | **Partial refunds (Quetzal Pagos):** Quetzal supports partial refunds (`amount_refunded < amount`). For v1 of this integration, any `charge.refunded` event maps to `Status__c = Refunded` on `Premium_Payment__c`, and `amountRefunded` is included in the canonical event for Finance consumers. | Salesforce `Premium_Payment__c` has a single `Status__c` picklist (`Pending`, `Captured`, `Failed`, `Refunded`) and one `Amount__c` field. | Part A, Part B |
| 5 | **Azure API Management (APIM) and OAuth2 boundary:** External payment providers cannot obtain OAuth2 tokens from Meridian's internal IdP; they authenticate exclusively via their native webhook HMAC signatures. APIM validates TLS, applies rate-limiting/WAF, strips internal headers, and injects a managed identity / internal OAuth2 token when forwarding to the backend intake service. | Reconciles public provider webhook specs (`reference/providers/`) with the ecosystem rule that internal APIs behind API Manager require IdP tokens. | Part A, Part C |
| 6 | **Existing Azure platform resources:** Azure API Management, Application Insights, Log Analytics workspace, and the OIDC/OAuth2 IdP are shared platform services managed outside this squad's repository. Our IaC references them via parameters/data sources rather than recreating them. | `SCENARIO.md` states these components already exist at the platform level. | Part A, Part C |
| 7 | **Data retention for operational tracking and idempotency:** Operational tracking records (FR7) and idempotency keys are retained for 90 days in the operational store, while raw PII is never persisted in logs or operational tables (only masked/hashed or omitted, keeping only provider/policy identifiers). | Covers provider retry windows (up to 48h/3 days), month-end reconciliation cycles, and NFR6 privacy rules. | Part A, Part D |
