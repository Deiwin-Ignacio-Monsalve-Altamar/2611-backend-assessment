# Azure Services Selection & Trade-offs

| Capability | Chosen Service | Why It Fits Meridian Mutual | Alternatives Considered |
|---|---|---|---|
| **Webhook Intake Compute** | **Azure Container Apps** | Scales rapidly on HTTP concurrency spikes during payment bursts, runs standard Java 21 Spring Boot containers, and integrates natively with Managed Identity and VNet without Kubernetes cluster management. | **AKS:** Too much operational overhead for a single microservice. **Azure Functions:** Cold-start latency can cause gateway webhook timeouts. |
| **Asynchronous Messaging** | **Azure Service Bus** | Guarantees at-least-once delivery, per-country isolation (`co`, `mx`, `cl`), built-in Dead-Letter Queues (DLQs), and controlled consumer concurrency to protect Salesforce's 24h API quota. | **Azure Event Hubs:** Optimized for high-volume log/telemetry streaming rather than transactional message completion and DLQ replay. |
| **Idempotency & State Store** | **Azure Cosmos DB (NoSQL)** | Single-digit millisecond reads/writes, native unique key constraint on `/paymentKey` to block duplicate retries, and `_etag` optimistic concurrency to prevent out-of-order state regressions. | **Azure SQL:** Higher connection-pool contention during sudden retry storms. |
| **Secret Management** | **Azure Key Vault** | Centralizes gateway HMAC secrets using RBAC + Managed Identity (no credentials in code or CI variables) and supports multi-version secret rotation without downtime. | **App Settings / Env Vars:** Higher risk of secret exposure and harder to rotate safely. |
| **Observability & Alerting** | **Application Insights + Azure Monitor** | Correlates webhook intake and consumer logs via `X-Correlation-Id` and triggers alerts on DLQ depth across all countries (`co`, `mx`, `cl`) and Salesforce `400`/`429` spikes. | **Self-hosted ELK/Prometheus:** Unnecessary maintenance burden. |
